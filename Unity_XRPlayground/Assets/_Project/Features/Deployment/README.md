# Generalized deployment runtime

This feature owns the common Isaac-to-Unity station lifecycle. The generated catalog is loaded from `Assets/Resources/XRPlayground/stations.json`; the authored source lives at the repository root in `deployment/stations.json`.

`StationRuntime` switches between Disabled, Mirror, and OfflinePolicy without fallback. `BridgeV2Client` and `MirrorRig` own streamed state. `PolicyRuntime`, `ArticulationRobotDriver`, and an `IStationAdapter` own offline execution. `PolicyRuntime` supports both feed-forward signatures and ordered static recurrent state pairs, retaining state between policy steps and clearing it on station reset. Contracts must prove observation normalization is embedded in ONNX; external or ambiguous normalization fails closed. Assistance is contact-gated and separately observable.

Editor workflow:

1. Import a licensed URDF with the pinned URDF Importer `0.5.2`. The approved immutable revisions and notices are recorded in the repository's `deployment/licenses/SOURCES.md`; AgiBot remains fail-closed because its local USD has no recorded redistribution terms. For UR10e/Robotiq, run `Isaac_XRPlayground/scripts/deployment/prepare_unity_robot_sources.py` first; it verifies both pinned Git revisions and generates the exact 16-link URDF, source mesh tree, and hash manifest without using a checkpoint.
2. Export the matching schema-6 `robot.definition.json` from the live Isaac articulation with `python -m XRPlayground.cli export --policy <id> --definition-only -- --device cpu --viz none`. The importer scans the central `RobotDefinitions` tree automatically. Its canonical physics hash remains available even when the source is a Nucleus URI rather than a local file. Fixed-link topology, typed collision geometry descriptors, resolved actuator PD gains, model/delay metadata, effort-limit curves, limited/continuous joint semantics, and any omitted body-to-body USD constraints are included; auxiliary constraints retain source identity, anchors, axis, and validated tree/loop roles. Old-checkpoint probes belong under `Bundles/References` and never participate in promotion.
3. Assign the generated `RobotDefinition` to an `ArticulationRobotDriver` on the imported root, or multi-select that definition with the imported root. The robot's catalog provenance must already be verified.
4. Use `XRPlayground/Deployment/Normalize Selected URDF Robot` and commit the resulting prefab. Normalization strips URDF-importer components and embeds a robot ID plus the canonical Isaac physics-definition hash. It refuses missing or duplicate links/joints and collision-shape count mismatches.
5. Select the normalized prefab and use `Install Selected Normalized Robot Rig`. The installer places an environment wrapper plus the catalog-authored Isaac robot offset in every matching station shell without overwriting an existing authored rig.
6. Run `Bind And Apply Isaac Physics` on the installed driver. Mass, COM, principal inertia, anchors, finite unit axes, limits, drives, maximum joint velocities, contact offsets, friction, and restitution come from Isaac. Revolute values remain radians in the transfer contract and are converted to Unity drive degrees; prismatic values remain meters. Unity has no per-collider rest-offset API, so absent/zero Isaac rest offsets are accepted and non-zero values fail closed until geometry preparation or nominal calibration resolves the mismatch. Golden traces record explicit per-joint and loop-closure position/velocity units.
7. Use `Bind Promoted Policy Release` before a build. The binder accepts only the active, complete six-policy `Bundles/Ready/catalog.json`, serializes its ONNX/contract assets into all matching runtimes (including Spot Follow's nested locomotion runtime), and disables the candidate override. Candidate and reference models never make an uncalibrated station production-ready.

For a local Spot Follow development build, use `Bind Local Spot Follow Candidates` after both corrected candidates have been exported. It accepts only the 250 Hz physics / 50 Hz locomotion 48-to-12 contract and the 5 Hz Follow 10-to-3 contract, leaves the candidate override visibly enabled, and never writes the promoted release catalog.

To play the checked-in Spot Follow candidate, open `SampleScene`, enter Play Mode, and press **Start Offline Policy** on the Spot panel. No Isaac process or bridge is required. The Follow target resolves to `Main Camera`; each explicit offline reset keeps Spot's position, faces it toward the current player position once, and then hands all twelve physical joints to the locomotion ONNX policy. The candidate uses a 1.25 m follow distance, a two-second gait ramp, calibrated drive damping, command-dependent joint-excursion fading, and contact-gated upright angular damping. It never translates or teleports the root while running.

The playable Unity safety profile keeps `unitySteeringAssistBlend = 1`, forward tracking enabled, and lateral/yaw tracking disabled because the current cross-engine articulation transfers sustained turns unreliably. Both high-level and locomotion ONNX models still execute at 5 Hz and 50 Hz respectively; the geometric guard supplies the stable forward command and the low-level ONNX remains the actuator controller. For parity diagnostics, set `unitySteeringAssistBlend = 0`, `unityCommandScale = 1`, and enable the unassisted diagnostic toggle. This is a local candidate, not a promoted six-station release.

For the checked-in Jaco2, UR10e/Robotiq, and Spot sources, `XRPlayground/Deployment/Build And Install USD Articulation Prefabs` performs steps 3 through 6 reproducibly. Primitive collision shapes missing from visual USD—such as Spot's feet—are created from the live Isaac descriptors. AgiBot is configured in this builder with a deterministic spanning tree and separately rooted Rigidbody proxies for its four passive revolute closures. Proxy initialization, external-joint telemetry, and anchor-drift behavior are tested; its explicit proxy mass must be calibrated. Prefab emission remains blocked while AgiBot redistribution terms are unverified. The generated prefabs and installed rigs still carry the same provenance, hash, hierarchy, and collider-count gates.

OfflinePolicy validates the rig identity again at activation: catalog robot ID, redistribution status, canonical physics-definition hash, articulation hierarchy, and collider counts must all match. A visual hierarchy or an unverified imported prefab cannot silently qualify as an offline robot.

After installation, select the `OfflineRig_*` wrapper and use `Configure Selected Offline Station Rig`. Semantic root/end-effector/contact link names and the robot offset come from the generated catalog. The tool builds the Ball, Conveyor, and Pick task physics at their Isaac dimensions and masses, wires contact-gated assistance, configures Spot feet/upright damping, and assigns the adapter without bypassing bundle or calibration gates.

Every shell also owns a golden-trace recorder, a 100-seed scenario evaluator, and an open-loop action player. The open-loop player suspends policy inference and applies contract-sized processed actions verbatim for Isaac/Unity system-response calibration. Partial traces and scenario runs are not promoted as evidence.

Balance Bot is the one procedural exception to the URDF flow. `XRPlayground/Deployment/Build Procedural Balance Bot Offline Rig` commits and installs a kinematic tray plus rigid balls using the authored Isaac dimensions, masses, friction and seeded spawn distribution. It still requires a calibrated `tray_120hz` profile and promoted policy bundle.

Tests live under `Tests/EditMode` and `Tests/PlayMode`. The scene builder is idempotent; legacy station components remain disabled until the six-station release gate passes.
